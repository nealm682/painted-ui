## F. "Is the gaming way the best way?" — settled position

The rAF loop is the right executor for painterly canvas targets. For
component targets the platform now provides superior executors: Web
Animations API (compositor-thread, battery-friendly) and the View
Transitions API (native shared-element morphs = our pageMorph verb).
Position adopted: **the choreographer is a compiler; executors are
backends** — canvas/rAF for painterly, WAAPI/View Transitions for DOM.
Innovation lives in the semantic layer, not loop loyalty. New planned
page: `concepts/executors`. This also answers the FPS-sometimes
inconsistency: it's two legitimate executors that were never named as
such — now they are.
