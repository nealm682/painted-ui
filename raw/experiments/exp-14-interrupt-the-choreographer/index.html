The measurement — velocity over time

A ease-in-out    B ease-out    C spring    retarget instant
Both tweens drop to zero at every retarget line. A duration tween is a scripted path from A to B, so a new instruction restarts the script from rest. The spring passes through continuously — its velocity is state, not a function of scripted position.
And the trade. Ease-in-out spends its opening barely moving — at 180 ms into a 500 ms tween it has delivered only 18.7% of the commanded distance — so under rapid fire it restarts the slow-in ramp forever and stalls. Ease-out delivers 73.8% in the same window, so it keeps up — but it is moving fastest exactly when it gets dead-stopped, so its snap is roughly twice as violent. Front-load the curve and you travel well but snap hard; back-load it and you snap softly but stall. There is no third easing that escapes. The spring does neither, because velocity carries.

Buttons — press them, and hold

press a button…
What to feel. The two spring buttons compress immediately on press — the spring front-loads velocity, so the response happens inside the first frames. Release and they overshoot slightly past rest before settling: that reads as a material with give. The tween button takes its ease-in ramp before anything visible happens, which is why it feels like it didn't register the press. Tap all three rapidly and the difference stops being subtle.

Two engines, visible side by side. typeSet is a performance — the word-by-word cadence is the content, so it runs on a time track. Emphasis is a state change — the headline has a new size and spacing to arrive at, with no opinion about the route — so it runs on springs, and you can interrupt it by hitting the buttons in any order.
